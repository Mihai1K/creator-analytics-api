# Reliability report — измеренная, не заявленная

Поле имеет ценность только если извлекается стабильно. Здесь — **фактические** цифры из
`scripts/stress_test.py` и живой проверки эндпоинтов, а не количество «заявленных» полей.
Правило: поле с fill-rate <80% авто-понижается до `low` и не может доминировать в Score.

bbbreaking, meduzalive, varlamov, mash, readovkanews, rbc_news, banksta, tass_agency,

- **Fetch-success: 75% (12/16); второй прогон — 61% (17/28)** при более высокой конкурентной
  нагрузке. В ОБОИХ прогонах у загруженных каналов parse fill-rate = **100% по всем 14 полям,
  0 авто-понижений** — паттерн устойчив на двух независимых выборках. Падения — не парсер, а
  **t.me anti-flood** (таймаут ~63с после ретраев); успешные грузятся ~1–2с. **Вывод для
  промышленного режима:** разносить запросы (пауза 2–3с), не гонять параллельные прогоны на один
  хост, либо брать объём через TGStat API.
- **Sample (durov):** 11.7M подп., median 5.74M просмотров, view_rate 0.49, spread 4.7,
  3.8 постов/нед, deleted_pct **0.048** (реалистично на плотной выборке 20 постов).

### Исправленный false-positive: deleted_pct
На тонкой выборке (6 постов) метод id-разрывов давал **ложные 62.5%** (t.me/s отдаёт узкое
окно, а message-id инкрементятся и для служебных сообщений). Фикс: считаем только при **≥10**
постах в окне, иначе `null`. После фикса durov = 4.8% (20 постов) — правдоподобно. Метрика
помечена как ориентировочная (низкая реальная надёжность на малых окнах).

## RuTube — верификация публичного API (2026-07-13)

Живая проверка **исправила две неверные claim'а** прошлого исследования:

| Эндпоинт | Статус | Вывод |
|---|---|---|
| `api/video/<id>/` | ✅ 200 JSON, ~0.6с | hits(views), author, category, tags, duration, **feed_subscribers_count**, is_ten_thousand(РКН) |
| `api/profile/user/<id>/` | ✅ 200 JSON | **subscribers_count** (проверено: 311 810) + name |

Без Cloudflare/CAPTCHA; 8 быстрых запросов подряд не заблокированы (тяжёлую нагрузку не тестировали →
rate-limit при масштабе помечен как непроверенный). Рабочие эндпоинты внесены в `extractors.md`.

## Метод
`stress_test.py` гоняет парсер по N профилям, считает per-field fill-rate + время, ставит
confidence (`high ≥95% · medium ≥80% · low <80%`) и авто-понижает нестабильные поля. Результат —
`reliability.json`. Прогонять по каждому провайдеру; решают цифры, а не заявления.
