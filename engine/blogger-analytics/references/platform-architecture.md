# Архитектура платформы — «Bloomberg, а не LabelUp»

LabelUp показывает **метрики**. Мы строим **систему принятия решений**, где метрики — лишь один из
источников. Не гнаться за количеством цифр (гонку не выиграть), а выиграть тремя вещами:
**1) собственная аналитика · 2) история и прогнозы · 3) AI-рекомендации «что делать дальше»**.

## Три независимых движка
```
Analytics Engine   →   Marketing Intelligence Engine   →   Decision Engine
(объективные цифры)     (смысл и продающая способность)     (действие)
```

### 1. Analytics Engine — объективные цифры (СВОИ метрики, не копия LabelUp)
Слой Data Engine собирает по площадкам в ЕДИНУЮ структуру `CreatorProfile { identity, audience,
content, engagement, commercial, contacts, compliance, history }` — дальше системе всё равно, TikTok
это или Telegram. Поверх — собственные метрики:
- **Audience Quality** (0–100) = прирост + стабильность + вовлечённость + частота + гео + возраст + отсутствие подозрительных скачков. (в движке: `quality.py`, + расширить)
- **Audience Pulse** = «Живая / Растёт / Падает / Вирусится» (не голый ER). (`snapshots.py` даёт динамику)
- **Commercial Index** = справедливая цена vs запрос vs переплата%. (`recommend.py` + decision-слой)
- **Content Stability** = публикаций за 90 дней + регулярность → «очень стабилен / рвано».
- **Virality** = среднее/максимум просмотров + индекс вирусности 0–100.

### 2. Marketing Intelligence Engine — смысл и «как блогер ПРОДАЁТ» (главный моат)
Это то, чего почти никто не делает. Не «сколько подписчиков», а «как он рекламирует»:
- **Brand Safety** (AI по последним ~100 публикациям): доли политика / алкоголь / мат / 18+ / азарт.
- **Тематики** (AI-классификация): авто 83% · lifestyle 71% · юмор 58% · трэвел 44%.
- **Рекламная насыщенность**: за 30 роликов — реклама 11, из них нативная 8 / прямая 3; частота «каждые 3,2 ролика» → усталость аудитории.
- **Конкуренты**: кого уже рекламировал (Яндекс, Ozon, WB, Avito) → совместимость/эксклюзив.
- **Качество интеграций** (AI): длительность, место (начало/середина/конец), есть ли CTA/промокод, естественность подачи.
- **Похожие блогеры** + пересечение аудитории.
Итог: «мы знаем, как блогер продаёт» — это невозможно скопировать сбором открытых метрик.

### 3. Decision Engine — действие (уже построено)
Не ER/CPM/CPV, а: **стоит покупать %, сколько платить, как торговаться, чем заменить, какой медиаплан,
какой результат ждать**. Реализовано: экран-решение (`webui/`), `recommend.py`, `deal_engine.py`.

## 5 уровней пайплайна
```
Data Engine (providers/*) → Analytics Engine → AI Engine (выводы: «просмотры +38% за 14д»,
«теряет аудиторию», «цена выше рынка на 28%») → History Engine (ежедневные Snapshots: сегодня→неделя→
месяц→год) → Decision Engine.
```

## Что реально собирается (честно, по площадкам)
- **Telegram** — почти всё публично (подписчики, просмотры, реакции, комментарии, частота, медиана, разброс). ✅ `telegram.py`
- **YouTube** — Data API v3 (подписчики, просмотры, лайки, комментарии, длительность, Shorts). ✅ (ключ)
- **VK** — VK API, почти всё. (токен)
- **TikTok** — без логина только шапка; полноценно — Research/Display API или согласие автора. ⚠️
- **RuTube** — публичный JSON (video/profile/person). ✅ (проверено)
- **Дзен** — открытые данные / студия владельца.
Marketing Intelligence (Brand Safety, тематики, ad-load, интеграции) требует ДОСТУПА К КОНТЕНТУ
последних постов → отлично работает на Telegram/YouTube/RuTube; на TikTok — только с логином/API.
Где данных нет — «недоступно → запросить», не выдумываем (принцип движка).

## Стратегическая ставка
Не победа количеством метрик, а **связка «своя аналитика + история/прогнозы + AI-действия»**.
Платформа перестаёт быть «сервисом статистики» и становится **виртуозным медиабайером, который думает
за пользователя** — это и есть главное конкурентное преимущество, которое трудно скопировать.

## ГЛАВНОЕ ПРАВИЛО ПРОДУКТА: наружу — одна сущность, **AI Media Buyer**
Пользователь НИКОГДА не видит названий внутренних модулей (Strategy AI, Learning Engine, Knowledge
Graph, Simulation, Recommendation). Для него существует один агент, который думает как лучший
медиабайер, и один конвейер:
```
Запрос → Стратегия → Подбор → Переговоры → Медиаплан → Прогноз → Запуск → Оптимизация
```
Внутренние имена живут только в коде и этой документации. Экран — `webui/buyer.html`.
Проверка: `grep "Deal Engine\|Knowledge Graph\|Recommendation Engine\|…" webui/*.html` = 0.

## ТЕСТ КАЖДОЙ ФИЧИ (жёсткое правило для команды)
**Помогает ли она принять лучшее маркетинговое решение?** Нет → не разрабатывается.
Это защита от превращения в «ещё один сервис с сотнями метрик».
Заморожено на v1 (не трогаем): новые поля · новые соцсети · новые коэффициенты.
Система уже умеет больше, чем пользователь способен переварить.

## Роадмап 3 месяца (утверждён CTO)
1. **Recommendation v2** — вместо «Подходит 87%» объяснение через накопленные знания. ✅ `explain.py`
2. **Learning** — главный приоритет: после каждой кампании автоматически сохранять
   бренд → блогер → стоимость → просмотры → CTR → CPC → CPA → ROMI → повторная закупка → оценка менеджера.
   Через год — актив на десятки млн ₽. ✅ `learning.py` (нужен хук на закрытие сделки + оценка менеджера)
3. **Simulation** — не только «убрать блогера», а «+120 000 ₽?», «убрать Telegram?», «микро→мидлы?»,
   «частота вместо количества авторов?». ⏳ `simulation.py` (есть убрать/заменить/долить)
4. **Optimizer** — через 5 дней после старта: «Стоп блогер №7: CTR −38%, CPA +64% → перелить 48 000 ₽
   в 3 и 11». Самый красивый агент. ⏳ нужен пост-запуск-трафик.

## Пять независимых AI-агентов (внутренняя архитектура v2)
Не один Recommendation Engine, а пять агентов вокруг брифа:
```
Бриф → Campaign AI → [ Strategy · Knowledge · Analytics · History ] → Simulation → Media Plan → Execution → Learning
```
| Агент | Отвечает на | Статус |
|---|---|---|
| **Strategy AI** | «Как вообще лучше потратить бюджет?» (микс, тест/масштаб, что НЕ делать) | ✅ `ai-strategy` workflow → `strategies.json` |
| **Planner AI** | «Собрал медиаплан: N авторов, охват, CPM, прогноз» | ✅ `recommend.py` |
| **Buyer AI** | «Кого купить, почему, сколько предложить, как торговаться, шанс согласия» | ✅ decision-слой + `deal_engine.py` |
| **Optimizer AI** | После запуска: «у блогера 7 низкий CTR → стоп, перелить в 18» (автобиддер) | ⏳ нужен пост-запуск-трафик |
| **Learning AI** | «Самокат: 20 запусков → TG 80–150k, женщины 25–35, CPA 184 ₽» | ✅ `learning.py` (леджер, копится с 1-й кампании) |

**Knowledge Graph хранит РЕЗУЛЬТАТЫ связей, а не связи.** Не «блогер → Wildberries», а
`brand → что рекламировали → оффер → CTA → формат → CPM → CPA → ROMI → повторил ли бренд`.
Реализовано: `learning.record()` пишет ребро `blogger -[РЕЗУЛЬТАТ{cpa,romi,offer,cta,format,repeat}]-> brand`.

**Simulation** (`simulation.py`) — не «прогноз 12 000 переходов», а дельты: убрать/заменить/долить →
Δохват, ΔCPM, Δстоимость, Δвероятность KPI (эвристика −0.65×ΔCPM%, ограничена ±100%, заменится моделью Learning на своих данных).

## ДЕНЬГИ ИДУТ ЗА ДОКАЗАТЕЛЬСТВАМИ (правило Recommendation v2, не коэффициент)
Найденный баг с денежными последствиями: сортировка «охват/рубль» систематически поднимала наверх тех,
о ком мы знаем МЕНЬШЕ всего. Неизмеренный охват оценивается оптимистично (0.5×подписчики) → фантомный
CPV 0.04 ₽ бьёт измеренный 5.42 ₽. Оценка всегда выигрывает у измерения, потому что оценка оптимистична.
Правила:
1. Измеренный охват (`median факт`) ранжируется выше оценочного — всегда.
2. На авторов с неподтверждённым охватом уходит не больше `test_share` (35%) бюджета; остальное — после
   подтверждения статистики автором (гейт оплаты в «Сделке»).
3. Довод «✔» разрешён, только если под ним данные. Цена на оценочном охвате = оценка÷оценку → это `?`, не `✔`.
4. Единый blended CPV не показываем: он усредняет измеренное с предположением.
Реальность базы: измеренный охват есть у **4 авторов из 25** — это и есть настоящий фронт работ.

**Приоритеты (по CTO):** 1) Learning Engine ⭐⭐⭐⭐⭐ 2) Simulation ⭐⭐⭐⭐⭐ 3) Recommendation+Knowledge Graph ⭐⭐⭐⭐ 4) Контент-аналитика ⭐⭐⭐.

## Философия: не «база блогеров», а AI Buying Platform
Рекламодатель платит НЕ за статистику. Он платит за ответ на вопрос:
**«Если я потрачу 300 000 ₽ — что произойдёт?»**. Вокруг этого и строим продукт: ИИ становится
медиабайером. Конкуренты отвечают на «какая статистика / есть ли накрутка / какая аудитория» — мы
отвечаем на «что купить, почём, что будет и чем заменить».

## Полный стек движков
```
                 Data Engine
                      │
        ┌─────────────┼─────────────┐
   Analytics     Marketing AI     History
        └─────────────┼─────────────┘
                      │
             Knowledge Engine        ← накопленные ЗНАНИЯ (моат)
                      │
              Learning Engine        ← обучение на фактических результатах
                      │
             Prediction Engine       ← вероятности, а не ER
                      │
             Simulation Engine       ← «что будет, если…»
                      │
   Decision → Campaign → Deal Engine
```
- **Knowledge Engine** (самая дорогая часть): не цифры, а знания. По блогеру — история интеграций
  (из 18 реклам 14 окупились, 4 нет), «что продаёт хорошо» (детские товары, спорт, маркетплейсы) и
  «что плохо» (банки, крипта, финансы), средний ROI по нишам, эффект «после рекламы WB +32%».
- **Learning Engine**: клиент купил рекламу → получил 842 регистрации → CPA 213 ₽ → **запоминаем**.
  Через год мы знаем не только блогера, а **что он реально продаёт**.
- **Prediction Engine**: не «ER 6,2%», а «вероятность набрать 1000 регистраций — 76%», «окупаемость 82%»,
  «ожидаемый CPA 170–240 ₽».
- **Simulation Engine**: «что будет, если заменить Weekain на Harry» → стоимость +38k, охват +1,8M,
  регистрации +640, риск +8%; «если +100k бюджета»; «убрать Telegram, добавить Shorts». (прототип есть в карточке)
- **Recommendation Engine ++**: не «похожие», а «лучше по цене / по аудитории / по CPA / по Brand Safety /
  под мобильное приложение».

## Настоящий moat — накопленная база знаний (data flywheel)
Не парсер, не AI, не интерфейс — их скопируют. Некопируемо то, что копится годами:
100k+ блогеров · история изменений каждого · история интеграций · **фактические результаты кампаний**
(реальные CPA/CPL/ROMI) · история переговоров и скидок · предпочтения рекламодателей · **AI-модели,
обученные на СОБСТВЕННЫХ данных**. Скопировав интерфейс и код, конкурент не получит данные и модели.

## Глубина > ширина (директива на 6–9 мес)
Не добавлять новые соцсети. Довести до максимальной глубины **Telegram · YouTube · TikTok · VK** —
чтобы по каждой можно было принять решение, не открывая сторонние сервисы.

## Миссия и тест каждой фичи
Миссия: **не самый большой каталог блогеров, а система, которая помогает принимать более выгодные
решения о закупке рекламы, чем человек вручную.**
Тест любой новой фичи одним вопросом: **«Она повышает качество решения медиабайера — или просто ещё
одна цифра на экране?»** Повышает решение → делаем. Просто цифра → нет.

## Приоритет разработки (сейчас)
